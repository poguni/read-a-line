1. 개요

항목 내용
앱 이름 한 줄 독서 (Read a Line)
한 줄 소개 연간 독서 목표를 빙고판과 미션으로 바꿔, 여러 분야의 책을 즐겁게 꾸준히 읽도록 돕는 개인용 웹앱
대상 사용자 본인 1명(개인 전용). 설계할 때는 새해 다짐형 직장인, 독서 모임 운영자, 편식 독서가, 학부모·교사를 사용 상황으로 참고
형태 단일 HTML 파일 웹앱 + Supabase 저장(Delicious Library 프로젝트 공유)
개발 기간 2026-11-05 기획 시작 → 2026-11-06 디자인·v1 → 2026-11-11~12 v2(로그인·동기화)와 추가 기능

2. 목표 및 배경

  • "올해 24권 읽기" 같은 숫자 목표는 중간에 동기를 잃기 쉽고, 익숙한 분야만 읽는 편식 독서도 흔합니다.
  • 빙고는 규칙이 단순하고 "한 줄만 더!"라는 심리가 작동해 꾸준함을 만들기 좋은 게임 형식입니다.
  • 핵심 가치 1. 게임처럼 즐겁게 — 칸을 채우고 줄을 완성할 때마다 시각적 보상 2. 다양하게 읽기 — 미션 칸이 새로운 분야로 안내 3. 내 속도에 맞게 — 3×3(9권)부터 5×5(25권)까지 판 크기 선택, "10일에 1권" 같은 필요 속도 안내 4. 가볍고 안전하게 — 설치 없이 파일 하나, 기존 Delicious Library 계정으로 로그인, 내 기록은 RLS로 나만 접근

6. 주요 의사결정과 이유

결정 이유
v1을 버리지 않고 그 위에 v2를 더함 v1이 PRD 기능과 테마 3종을 이미 구현했고, 시안도 같은 코드를 쓰므로 다시 만들 이유가 없음
전용 스키마 read_a_line + ral_ 접두어 Delicious Library(public, bookchronicle)에 영향 없이, drop schema 한 줄로 제거 가능
대기열 대신 "마지막 서버 상태 스냅숏과의 차이" 동기화 기존 기능 코드(수십 곳의 상태 변경)를 건드리지 않고, 실패해도 같은 차이를 다시 보내면 되어 단순하고 안전함
로그아웃은 signOut({ scope: 'local' }) 기본값(global)은 같은 계정의 모든 세션을 끊어 Delicious Library 로그인까지 풀릴 수 있음
다른 계정으로 로그인하면 이전 캐시 삭제 관리자·테스트 계정을 오갈 때 기록이 섞이지 않게
둘러보기(샘플)는 저장하지 않음 v1은 샘플을 실제 기록으로 저장했으나, 로그인 계정에 샘플이 올라가는 것을 막기 위해 변경
보상은 연도별로 관리 판 크기를 바꾸거나 새 판을 만들어도 그해의 보상 약속이 유지되도록
칸 옮기기는 미션+책을 통째로 교환, FREE 칸 고정 가운데 무료 칸의 의미를 지키고, 채운 기록이 엉뚱한 미션으로 붙지 않게
효과음은 소리 파일 없이 Web Audio 합성 단일 파일·외부 의존성 최소 원칙 유지, 테마별 음색도 쉽게
화면 이동을 pushState로 기록 브라우저 뒤로 가기가 앱을 빠져나가던 문제 해결
판을 지워도 책은 유지, 마지막 판을 지우면 새 판 만들기로 책 기록은 연간 진행률의 기준이라 판과 독립적으로 보존
고풍 서재 글꼴을 고운돋움으로 통일 명조·바탕 계열이 작은 글자에서 읽기 어렵다는 사용자 피드백
공개(publishable) 키만 앱에 넣음 RLS로 보호되므로 공개돼도 안전, service_role 키는 사용 금지

7. 문제 해결 기록

문제 원인 해결
로그인은 되는데 저장 실패(PGRST106) read_a_line이 Data API에 노출되지 않음. MCP·SQL로는 바꿀 수 없는 설정 사용자가 대시보드 Exposed schemas에 추가 → REST 응답으로 확인
페이지를 연 직후 0.4초 동안 클릭이 무시됨 끌기 직후 클릭을 막는 변수 dragEndedAt의 초기값이 0이라, 처음 0.4초가 "방금 끌기 끝남"으로 판정됨 초기값을 -Infinity로 변경
세션 확인 중에 둘러보기를 누르면 계정 기록이 섞일 위험 비동기 세션 복원이 둘러보기 상태를 덮어쓸 수 있음 세션 확인 뒤 둘러보기 중이면 로그인 처리를 건너뜀
다시 만든 시안 페이지에서 스크립트 문법 오류 bash heredoc이 역슬래시 하나를 먹어 </script>가 이스케이프되지 않음 → HTML 파서가 스크립트를 중간에 끊음 변환 스크립트를 파일 쓰기 도구로 작성하고 String.fromCharCode(92)로 역슬래시 생성, </script> 개수로 검증
문서·앱 파일 줄바꿈이 CRLF로 바뀜 Windows에서 Python 텍스트 모드 쓰기가 \n을 \r\n으로 변환 원본(LF)과 비교해 되돌리고, 이후 Node 스크립트나 newline 지정으로 작성
모바일 보상 설정 창에서 태그·삭제 버튼이 다음 줄로 밀림 행이 flex-wrap이라 좁은 화면에서 줄바꿈 한 줄 유지(nowrap), 입력 칸이 줄어들도록 조정, 선택지 문구 단축
마지막 판을 지운 뒤 다시 로그인하면 책이 안 보일 위험 서버 데이터에 판이 없으면 "기록 없음"으로 처리하던 조건 판·책·보상이 모두 없을 때만 빈 상태로 판단하도록 수정
MCP SQL 실행 승인이 만료됨 승인 대기 2분 초과 재요청(결과를 지우던 SQL 한 줄도 함께 수정)

8. 보안/성능 고려사항

보안

  • 6개 테이블 모두 RLS(본인 행만). 로그인하지 않은 요청은 401로 차단됨을 확인
  • 다른 계정의 기록 조회·수정·삭제 0행, 다른 사람 이름으로 저장하는 시도는 권한 오류로 차단됨을 확인
  • 앱에는 공개 키만 포함, service_role 키는 저장소·코드에 없음. .gitignore에 .env 등록
  • 인증 설정은 바꾸지 않음(Delicious Library와 공유). 참고: 프로젝트의 회원 가입이 열려 있고(이메일 인증 필요), "유출된 비밀번호 차단"이 꺼져 있다는 권고가 있음 — 두 앱에 함께 적용되는 설정이라 사용자 판단으로 남김
  • 사용자 입력은 esc()로 이스케이프해 화면에 출력

성능

  • 바뀐 행만 보내므로 평소 저장 요청은 1~3건, 변경이 없으면 0건
  • localStorage 캐시로 로그인 확인 전에 마지막 화면을 먼저 표시
  • board_cells.user_id 인덱스 추가(Supabase 성능 권고)

10. 배포

  • 방식: GitHub 저장소에 올리고 GitHub Pages(main 브랜치 루트)로 배포 — 사용자가 직접 진행 예정
  • 무료 계정에서는 공개 저장소가 필요. 공개 키는 RLS로 보호되어 노출돼도 안전
  • 이메일+비밀번호 로그인이라 Supabase Redirect URL 설정은 필요 없음(매직 링크 도입 시 Pages 주소 추가)
  • 커밋 대상 13개 파일을 .gitignore로 검증(.omc/, .playwright-mcp/, .env 등 제외)
  • 배포 URL: 아직 없음

11. 알려진 한계

  • 다른 기기의 변경은 실시간이 아니라 앱으로 돌아올 때(30초 간격) 다시 불러옴
  • 같은 기록을 두 기기에서 동시에 오프라인으로 고치면, 나중에 저장한 쪽이 이김(혼자 쓰는 앱이라 허용)
  • Supabase 기본 조회 한도(요청당 1,000행) 때문에 책이 1,000권을 넘으면 일부가 안 불러와질 수 있음
  • 실제 휴대폰에서의 길게 누르기와 효과음이 실제로 들리는지는 아직 확인하지 못함
  • 판 삭제·새 판 만들기의 실제 서버 반영은 로직 테스트로만 확인
  • 칸 옮기기를 키보드로 하는 방법이 없음
  • 공유 이미지에 보상 정보는 들어가지 않음
  • 다크 모드, 난이도 옵션, 6×6 판, "한 권으로 여러 칸 인정"은 미구현
  • PRD 일부 문단에 예전 이름 "보관함"이 남아 있음(맞춤법 검사에서 발견, 수정 여부 미정)

12. 향후 개선 아이디어 / 업데이트 계획

다음에 하면 좋을 것

  • 실제 휴대폰에서 끌기·효과음·화면 확인, 판 삭제·새 판의 서버 반영 확인
  • PRD의 "보관함" 표현을 "판 관리"로 정리
  • GitHub Pages 배포 후 배포 주소로 로그인·저장 점검
  • 키보드로 칸 위치 바꾸기(칸 상세 창에 "위치 바꾸기")

여유 있으면

  • 다크 모드(시스템 설정 연동)
  • 난이도 옵션(쉬움·보통·도전)에 따른 미션 추천
  • 6×6 판, 한 권으로 여러 칸 인정 옵션
  • 보상 달성 기념 공유 이미지, 블랙아웃 기념 이미지 꾸미기
  • 책이 많아졌을 때를 대비한 나눠 불러오기(1,000행 한도 대응)
  • PWA(홈 화면 추가, 오프라인 캐시 강화)

아이디어 수준

  • 독서 모임 모드: 같은 판 코드로 참여하고 멤버별 진행 이미지 합치기
  • 도서 검색 API로 표지·쪽수·분야 자동 입력
  • 월간 미니 빙고(3×3)와 연간 빙고(5×5) 동시 운영
  • 배지·업적(첫 빙고, 블랙아웃, 10개 분야 정복)
  • Delicious Library 장서에서 읽은 책 불러오기(읽기 전용)
